Function is_retryable_transport_error

fn is_retryable_transport_error(
    error: &(dyn Error + 'static),
    allow_mid_flight: bool,
) -> bool
Expand description

Returns true for reqwest transport errors that are safe to retry.

  • Connect failures never reached the server: always safe.
  • Mid-flight failures (request timeout, connection dropped while sending the request or while streaming the response) are only safe when allow_mid_flight is set, i.e. the command is idempotent: the server may have already applied a mutating command, and re-issuing it would apply it twice (double spend, extra blocks).
  • Unparsable responses ([reqwest::Error::is_decode]) are never retryable: bitcoind answers HTTP rejections such as 401 (bad auth) or 404 (unknown wallet) with a non-JSON body, which surfaces as a decode error. Decode errors caused by transport EOF (is_transport_eof_decode) are the exception: they are mid-flight failures.
