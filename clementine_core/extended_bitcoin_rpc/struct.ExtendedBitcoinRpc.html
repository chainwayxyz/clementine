pub async fn collateral_check( &self, operator_data: &OperatorData, kickoff_wpks: &KickoffWinternitzKeys, paramset: &'static ProtocolParamset, db: &Database, ) -> Result<bool, BridgeError>

Checks if an operator is still safely usable in the protocol.

This validates:

  1. The collateral UTXO exists with the correct amount and script
  2. The round chain is followed to the current collateral position
  3. The current collateral is not spent outside the protocol
  4. Every already-passed round (ready-to-reimburse is on chain) has no leftover kickoff UTXOs. UnspentKickoff cannot slash those once the next round spends the ready-to-reimburse burn connector, so leftover kickoffs can later be used with already-mined reimburse connectors.
  5. If a passed-round kickoff UTXO was spent as a kickoff, that kickoff’s finalizer must also be spent. An in-flight kickoff in a passed round is not watched by the round state machine. This uses the actual spending transaction of each leftover kickoff UTXO, including kickoffs that commit to a deposit that is not yet signed.

db is the bitcoin syncer. Kickoff UTXOs of finished rounds are looked up there; we only load block bodies for spends that might be kickoffs.

Spent-or-not comes from the syncer, not from bitcoind. If the syncer has no spend for a kickoff UTXO in a finalized block, treat it as still live and reject. A short mismatch with bitcoind is fine on mainnet.

§Returns
  • bool: true if the operator is still in protocol and safe to include in deposits

async fn passed_round_kickoffs_are_safe( &self, round_txhandler: &TxHandler, round_idx: RoundIndex, paramset: &'static ProtocolParamset, operator_data: &OperatorData, db: &Database, ) -> Result<bool, BridgeError>

Returns false if a passed round still has a live kickoff UTXO, or an in-flight kickoff whose finalizer is unspent.

Kickoff UTXOs of this finished round must all be spent. Spent-or-not comes from the syncer, not from bitcoind. A spend counts only if its block is finalized. No such spend means the UTXO is still live: reject. Do not add a gettxout check. A short mismatch with bitcoind is fine on mainnet.

A tx that spends more than one of these UTXOs cannot be a protocol kickoff (those have a single input), so it is a burn and its block is not loaded. Other spends are loaded from their blocks. Sequence is the first filter: burn / UnspentKickoff set CSV, so a relative locktime cannot be a kickoff. After that it is a protocol kickoff only if it has exactly one input, version 3, the kickoff output layout, and the kickoff OP_RETURN (move_txid || this operator's xonly pk). Any other Winternitz spend still uses up the UTXO.

pub async fn create_fee_bump_tx( &self, txid: Txid, fee_rate: FeeRate, ) -> Result<Option<Transaction>, BitcoinRPCError>

Builds and signs a Replace-By-Fee (RBF) replacement of an unconfirmed transaction that meets or exceeds a target fee rate. It does not broadcast the replacement, so the caller can persist it first.

It works as follows:

  1. If the transaction is already confirmed, returns Err(TransactionAlreadyInBlock)
  2. If the current fee rate is already >= the requested fee rate, returns None
  3. Otherwise, increases the fee rate by adding the node’s incremental fee to the current fee rate, builds the replacement with psbtbumpfee, then signs and finalizes it with the wallet

Note: This function currently only supports fee payer TXs.

§Arguments
  • txid - The transaction ID to bump
  • fee_rate - The target fee rate to achieve
§Returns
  • Option<Transaction>: The signed replacement, or None if no bump was needed.
§Errors
  • TransactionAlreadyInBlock - If the transaction is already confirmed
  • BumpFeeUTXOSpent - If the UTXO being spent by the transaction is already spent
  • BumpFeeError - For other errors with fee bumping

pub async fn get_fee_rate( &self, network: Network, mempool_api_host: &Option<String>, mempool_api_endpoint: &Option<String>, mempool_fee_rate_multiplier: u64, mempool_fee_rate_offset_sat_kvb: u64, fee_rate_hard_cap: u64, ) -> Result<FeeRate, BitcoinRPCError>

Gets the current recommended fee rate in sat/vb from Mempool Space and Bitcoin Core and selects the minimum. For Regtest and Signet, it uses a fixed fee rate of 1 sat/vB.

§Logic
  • Regtest: Uses a fixed fee rate of 1 sat/vB for simplicity.
  • Mainnet, Testnet4 and Signet: Fetches fee rates from both Mempool Space API and Bitcoin Core RPC and takes the minimum.
  • Hard Cap: Applies a hard cap from configuration to prevent excessive fees.
§Fallbacks
  • If one source fails, it uses the other.
  • If both fail, it falls back to a default of 1 sat/vB.
